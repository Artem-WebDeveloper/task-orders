# Task Orders

Система управления нарядами для выездных бригад с авторизацией, ролями, CRUD-операциями и обновлениями в реальном времени через WebSocket.

---

## Quick Start

### Docker

Для запуска требуется `Docker`

```bash
npm run demo
```

Приложение будет доступно на `http://localhost`. Данные и роли за seed-ятся автоматически при первом запуске.

## Как работает 2FA

Двухфакторная аутентификация имитируется — код не отправляется на телефон, а выводится в консоль сервера:

1. Вводите телефон и пароль на экране входа
2. В терминале, где работает сервер, появится 6-значный код
3. Вводите этот код в поле «Код подтверждения»
4. Вы авторизованы

В продакшне вместо `console.log` здесь будет SMS-шлюз (Twilio, Vonage и т.д.).

## Почему Socket.IO, а не RabbitMQ

Проект рассчитан на **один инстанс** — один процесс Node.js, один WebSocket-сервер. В этом сценарии Socket.IO полностью покрывает потребности в реальном времени: аутентификация по JWT, room'ы по ролям, доставка событий нужным клиентам.

RabbitMQ становится необходим при **горизонтальном масштабировании** — нескольких инстансах бэкенда за балансировщиком. Тогда события одного инстанса нужно доставлять другим, и для этого используется шина сообщений. Для текущего масштаба проекта это избыточная сложность.

## Архитектура

```
task-orders/
├── backend/          Express API + Socket.IO сервер
├── frontend/         SPA на React + Vite
└── packages/shared/  Zod-схемы, используемые и фронтом, и бэком
```

**Monorepo** с npm workspaces. Общий пакет `@task-orders/shared` содержит Zod-схемы валидации — это гарантирует единообразие проверки данных на клиенте и сервере.

**Роли и доступ:**

- **Оператор** — CRUD-операции с нарядами, просмотр бригад, назначение исполнителей
- **Бригада** — просмотр только своих нарядов, смена статуса по схеме `new → in_progress → done`

**Реальное время:**

Сервер рассылает WebSocket-события по room'ам: `operators` (все операторы) и `team:{uuid}` (конкретная бригада). При изменении/создании/удалении наряда обновления приходят мгновенно без перезагрузки.

**Auto-seed:**

При старте сервер проверяет наличие ролей в БД. Если таблица пуста — заполняет ее тестовыми данными (2 оператора, 3 бригады, 8 нарядов со статусами new/in_progress/done).

**Примечание:** бэкенд транспилируется на лету через `tsx`, без отдельного шага компиляции в JS. Это упрощает dev-процесс. Для продакшена можно заменить на `tsup`/`esbuild`.

## Возможности

### Оператор

- Создание, редактирование, удаление нарядов
- Назначение бригады-исполнителя
- Автоматическая фильтрация (видит все наряды)
- Управление бригадами (просмотр списка)
- Обновления в реальном времени через WebSocket

### Бригада

- Просмотр только назначенных нарядов
- Смена статуса: `Новый` → `В работе` → `Выполнен`
- Обновления в реальном времени через WebSocket
- Мобильная навигация (bottom-nav)

### Общее

- Авторизация по телефону + пароль
- 2FA (имитация — код в консоль сервера)
- Темная и светлая тема
- Lazy loading страниц
- Валидация форм (Zod)
- Защита маршрутов (роли)
- Rate limiting на auth-эндпоинтах
- Защита HTTP-заголовков (Helmet)

## API Endpoints

| Метод    | Путь                          | Описание                        | Доступ         |
| -------- | ----------------------------- | ------------------------------- | -------------- |
| `POST`   | `/api/v1/auth/login`          | Запрос входа (телефон + пароль) | Все            |
| `POST`   | `/api/v1/auth/verify-2fa`     | Подтверждение 2FA-кода          | Все            |
| `POST`   | `/api/v1/auth/logout`         | Выход (удаление сессии)         | Авторизованные |
| `GET`    | `/api/v1/auth/me`             | Текущий пользователь            | Авторизованные |
| `GET`    | `/api/v1/users`               | Список пользователей            | Оператор       |
| `GET`    | `/api/v1/users/teams`         | Список бригад                   | Оператор       |
| `GET`    | `/api/v1/orders`              | Список нарядов                  | Авторизованные |
| `GET`    | `/api/v1/orders/:uuid`        | Детали наряда                   | Авторизованные |
| `POST`   | `/api/v1/orders`              | Создание наряда                 | Оператор       |
| `PATCH`  | `/api/v1/orders/:uuid`        | Редактирование наряда           | Оператор       |
| `DELETE` | `/api/v1/orders/:uuid`        | Удаление наряда                 | Оператор       |
| `PATCH`  | `/api/v1/orders/:uuid/status` | Смена статуса наряда            | Бригада        |

## WebSocket Events

| Событие                | Кому                | Триггер                                         |
| ---------------------- | ------------------- | ----------------------------------------------- |
| `order:created`        | Назначенная бригада | Создание наряда с исполнителем                  |
| `order:deleted`        | Назначенная бригада | Удаление наряда                                 |
| `order:status_changed` | Операторы + бригада | Смена статуса наряда                            |
| `order:assigned`       | Назначенная бригада | Назначение/смена исполнителя при редактировании |
